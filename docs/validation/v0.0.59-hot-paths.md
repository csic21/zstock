# 0.0.59 render hot-path checks

Measured on 2026-10-09 in an isolated Linux x86_64 container, Rust 1.97.1.
These are deterministic development-test microbenchmarks (`opt-level = 1`,
debug information disabled), not release-build frame-rate or device UX results.
The same test binary runs the old equivalent operation and the replacement on
identical synthetic inputs. Each case was repeated three times.

| Operation | Fixture | Before (ms) | After (ms) |
| --- | --- | --- | --- |
| Single-position lookup | 20,000 trades, 500 symbols, 40 lookups | 132.064 / 142.465 / 145.700 | 4.323 / 5.214 / 4.418 |
| Compiled champion lookup | 2,000 lookups, one retained strategy | 103.679 / 101.711 / 152.416 | 6.366 / 5.121 / 5.223 |

The median ratios are approximately 32x and 20x for these operations only.
Do not present them as an app-wide speedup, native navigation latency, or FPS.
Native screenshot smoke tests also do not establish frame-time performance.

## Reproduce

```sh
cargo test --bin stock performance_single_position_render_lookup -- --ignored --nocapture --test-threads=1
cargo test --bin stock performance_compiled_champion_render_lookup -- --ignored --nocapture --test-threads=1
```

## Correctness boundaries

- Position replay retains transaction order, fees, closed-position handling,
  names, and `(currency, code)` grouping. Equivalence fixtures include multiple
  currencies, partial sales, closed/reopened holdings, and missing instruments.
- The strategy cache holds immutable compiled execution specifications only.
  Library refresh clears and rebuilds it; render lookup follows the current
  champion identity. Observation-driven ranking changes are tested.
- Holdings, market prices, climate, and plans are not retained in that cache.
- Cached daily bars retain the same series identity; only an intermediate copy
  was removed.

For complete native performance acceptance, use the separate A6 protocol and
record actual device/build information. That device-level run is not claimed by
this document.
