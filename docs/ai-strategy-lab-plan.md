# ZStock AI 策略实验室实施计划

状态：提案，待实施  
制定日期：2026-08-09  
适用项目：ZStock（Rust + GPUI）  
估算口径：1 名主开发者；工期表示工作量，不是发布日期承诺  
首版定位：A 股日线、本地研究、批量回测、模拟观察；不连接券商、不自动下单

## 0. 如何使用本计划

本文件是后续 AI 或开发者的实施依据。执行时遵循以下规则：

1. 按阶段和 PR 顺序实施，不把策略 DSL、数据迁移、回测引擎和 UI 混在一个大改动中。
2. 每个 PR 必须保持可编译、可测试、可回滚；不得破坏现有行情、图表、持仓和轻量回测。
3. 先解决回测正确性，再接入 AI。AI 生成能力不能先于本地策略校验器和确定性执行引擎。
4. AI 只能生成受限的结构化策略定义，禁止生成并执行任意 Rust、Python、Shell 或 SQL 代码。
5. AI 不能决定策略是否晋级，只能生成候选和解释本地统计结果。
6. 所有回测必须记录策略版本、数据集版本、成本模型版本、成交规则和验证方法。
7. 新功能使用 `domain/services/infrastructure/features` 边界，不继续向 `AppState` 添加大量字段。
8. 仓库命令遵守项目 `AGENTS.md`，通过 `rtk` 运行，例如：

   ```bash
   rtk cargo fmt --all -- --check
   rtk cargo clippy --all-targets -- -D warnings
   rtk cargo test --all-targets
   ```

## 1. 项目目标

建设一个“AI 提出假设、本地程序验证假设”的策略实验室：

```text
用户设置研究目标、股票池、周期和风险限制
→ AI 一次生成 3–5 个结构化策略草案
→ 本地校验、规范化、版本化和去重
→ 在冻结数据集上批量回测
→ 执行样本外、滚动窗口和压力测试
→ 确定性晋级规则给出证据等级
→ AI 总结策略差异、风险和失效原因
→ 用户保存为“继续研究”或“模拟盘候选”
```

### 1.1 首版完成标准

- 用户可以在应用内创建实验并生成多个策略。
- 只有通过本地校验的策略才能运行。
- 50–100 只股票、3–5 个策略可以批量回测。
- 报告包含收益、风险、成本、基准、样本量、样本外结果和版本信息。
- 相同策略、相同数据集、相同配置得到完全一致的结果。
- 系统只输出“淘汰 / 继续研究 / 模拟盘候选”，不输出“建议实盘”。
- 模拟盘信号不触发真实交易。

### 1.2 首版范围

支持：

- A 股日线策略。
- 自选股或冻结的流动性股票池快照。
- MA、EMA、RSI、MACD、BOLL、ATR、成交量、收益率、N 日高低点。
- 收盘生成信号，下一交易日开盘成交。
- 固定持有、条件退出、止损、止盈和最长持有期。
- 固定比例仓位、最大持仓数、现金约束。
- 佣金、印花税、其他费用和滑点。
- 训练、验证、封存测试以及滚动样本外验证。
- 本地持久化实验、策略、数据集和回测报告。

暂不支持：

- 分钟级、高频或日内撮合。
- 港股、期货、期权、融资融券和做空。
- 基本面、新闻、公告和情绪事件策略。
- AI 生成并执行任意程序代码。
- 无限制参数暴力搜索。
- 券商连接、自动下单或真实资金管理。
- 把当前股票池误称为历史沪深 300；没有历史成分股数据时只能称为“股票池快照”。

## 2. 当前项目基线

### 2.1 已有能力

- `src/domain/backtest.rs` 已有纯 Rust 回测基础、成本模型、样本外数量、置信区间和证据等级。
- `src/data/backtest.rs` 已有 MA20 上穿、RSI 离开超卖、20 日突破三个本地规则。
- `src/data/ai.rs` 已支持本地规则、OpenAI Responses、兼容 Chat API 和多个本地 CLI。
- `src/services/market_data.rs` 已定义行情和 K 线 Provider 接口。
- `src/infrastructure/storage/json_store.rs` 已支持原子 JSON 写入、迁移备份和恢复。
- 项目已有行情、指标、候选扫描、决策卡、持仓和日记能力。
- 2026-08-09 本地检查基线：格式检查通过、Clippy 零告警、143 个测试通过、17 个联网测试忽略。

### 2.2 必须先解决的问题

1. 当前策略是硬编码枚举，无法表达 AI 生成的组合规则。
2. 当前回测只运行当前标的可见 K 线，不支持股票池或组合资金。
3. 当前数据集版本只包含起止时间和样本数；价格内容变化后版本可能不变。
4. 当前样本外平均交易收益与全周期基准收益直接相减，统计口径不一致。
5. 当前最大回撤只基于交易结束后的权益点，不能反映持仓期间回撤。
6. 当前证据等级对样本外数量、滚动窗口稳定性和多重筛选偏差约束不足。
7. 当前基准是当前标的同期买入持有，不能直接用于多标的组合回测。
8. 当前免费 K 线约 640–1000 根，且缺少退市股票和历史成分股，存在幸存者偏差。
9. `KlineProvider` 尚未形成批量、持久化、可冻结的数据集服务。
10. `src/data/ai.rs` 同时包含快照、提示词、HTTP、CLI 和解析逻辑，后续应抽取独立 LLM 端口。
11. `StockApp` 虽已有聚合状态，但仍通过 `legacy: AppState` 兼容约 152 个旧字段；策略实验室不得继续扩张该对象。

## 3. 不可违反的正确性约束

### 3.1 时间与前视约束

- 信号日为 `t` 时，策略只能读取 `<= t` 的数据。
- 默认成交发生在 `t+1` 的有效开盘价。
- 指标必须按历史前缀或等价的因果算法计算，禁止引用未来预计算结果。
- 财务和事件数据以后接入时必须按公告日期 point-in-time 处理。
- 修改 `t+1` 之后的数据不能改变 `t` 及以前的信号。

### 3.2 数据约束

- `DatasetId` 必须由数据内容哈希生成，至少包含市场、标的、日期、OHLCV、来源和复权方式。
- 数据集一旦用于封存测试，不得原地修改；更新数据必须创建新版本。
- 缺失、停牌、无效价格和重复日期必须显式记录，不能静默补零。
- 前复权数据仅作为首版研究数据；报告必须标明其历史价格可能随复权因子更新而变化。
- 没有历史成分股和退市样本时，报告必须标注幸存者偏差未解决。

### 3.3 执行约束

- 手续费按双边计算，卖出税费只在卖出侧计算。
- 成本模型需要支持最低佣金、滑点、其他费用和版本号。
- A 股数量按 100 股整数手处理；卖出规则需要允许清仓尾数。
- 无有效开盘价、停牌或无法成交时必须有确定性处理规则。
- 首版不假装能够精确判断涨停板排队成交；数据不足时采取保守成交规则并在报告中说明。
- 同一策略是否允许加仓、重叠持仓和重复信号必须明确配置。

### 3.4 统计约束

- 策略与基准必须使用同一时间区间和同一收益频率对齐。
- 最大回撤从逐日权益曲线计算。
- 样本外表现必须独立计算，不能用全周期基准替代样本外基准。
- 不允许只显示胜率；必须同时显示交易数、盈亏比、回撤和成本。
- 置信区间不得暗示独立同分布；优先使用按时间或标的分块 bootstrap。
- 生成候选数量和参数尝试次数必须记录，用于识别多重筛选和回测过拟合。

### 3.5 AI 边界

- AI 输出先作为不可信输入处理。
- 输出大小、策略数量、嵌套深度、周期和参数范围必须设上限。
- 本地解析、校验、规范化、哈希和编译全部通过后才能执行。
- AI 不得读取封存测试集指标后再次修改同一策略。
- AI 总结不能改变排行榜、证据等级或晋级结果。

## 5. 核心领域模型

### 5.1 标的标识

不要只使用裸字符串代码，新增：

```rust
pub struct InstrumentId {
    pub market: Market,
    pub asset_type: AssetType,
    pub code: String,
}
```

`AssetType` 首版至少包含 `Stock` 和 `Index`，避免股票代码和指数代码冲突。

### 5.2 策略定义

建议使用 Serde tagged enum 表达条件，不直接存储源代码。示例 JSON：

```json
{
  "schema_version": 1,
  "name": "MA20 回踩反弹",
  "hypothesis": "中期趋势向上时，短期回踩后恢复可能延续趋势",
  "timeframe": "1d",
  "universe": { "kind": "dataset_snapshot", "id": "universe-sha256" },
  "entry": {
    "all": [
      {
        "compare": {
          "left": { "indicator": "close", "lag": 0 },
          "op": "above",
          "right": { "indicator": "sma", "period": 20, "lag": 0 }
        }
      },
      {
        "crosses_above": {
          "left": { "indicator": "rsi", "period": 14, "lag": 0 },
          "right": { "constant": 40.0 }
        }
      }
    ]
  },
  "exit": {
    "any": [
      { "hold_days": 10 },
      { "stop_loss_pct": 6.0 },
      { "take_profit_pct": 12.0 }
    ]
  },
  "position": {
    "size_pct": 20.0,
    "max_positions": 5,
    "allow_pyramiding": false
  },
  "metadata": {
    "generator": "local-template-or-model",
    "prompt_version": "strategy-generator-v1"
  }
}
```

首版限制：

- 条件嵌套深度不超过 6。
- 单个入场或退出表达式节点不超过 32 个。
- 指标周期为 2–250。
- `lag` 只能为 0 或正数，含义为当前或过去，禁止负数表示未来。
- 止损为 0.5%–30%，止盈为 0.5%–100%，最长持有为 1–250 个交易日。
- 单策略最大持仓数和仓位总和必须通过资金约束校验。
- 必须存在明确退出或最大持有期。

### 5.3 数据集清单

```rust
pub struct DatasetManifest {
    pub id: String,
    pub created_at: String,
    pub market: Market,
    pub adjustment: Adjustment,
    pub source_versions: Vec<String>,
    pub instruments: Vec<InstrumentId>,
    pub interval: DateInterval,
    pub content_sha256: String,
    pub known_biases: Vec<String>,
}
```

### 5.4 实验

实验必须记录：

- 用户研究目标和风险限制。
- AI 模型、提示版本、原始候选数量和校验失败数量。
- 策略 ID、规范化哈希和父策略 ID。
- 数据集、股票池、基准和成本模型版本。
- 训练、验证、测试和滚动窗口配置。
- 参数尝试次数。
- 开始、完成、取消和失败状态。
- 排名规则、证据等级和晋级原因。

## 6. 实施阶段

## S0. 修正当前回测基线

工作量：2–3 天。  
依赖：无。  
目标：在扩展前保证现有回测统计口径可信。

任务：

- 将 `src/domain/backtest.rs` 拆成可逐步扩展的模块，或者先保持文件不动但补齐正确性测试。
- 修正样本外交易收益与基准收益的时间对齐。
- 生成逐日策略权益曲线，并从逐日权益计算最大回撤。
- 明确空仓期间现金收益为 0，基准仍按同区间逐日收益计算。
- 将数据集版本升级为内容哈希；哈希包含全部 Candle 内容和元数据。
- 收紧 `EvidenceGrade`：样本外交易不足时不得进入高等级。
- 在报告中明确区分总周期、训练、验证和测试统计。
- 保持原有三个规则继续可用。

必须新增的测试：

- `future_data_change_does_not_change_past_signal`
- `dataset_hash_changes_when_price_changes`
- `oos_strategy_and_benchmark_use_same_interval`
- `daily_drawdown_includes_intratrade_loss`
- `one_positive_oos_trade_cannot_be_multi_period_stable`
- `costs_are_applied_on_correct_sides`
- `same_fixture_produces_identical_report`

退出条件：

- 旧 UI 可以继续运行三个轻量规则。
- 固定 fixture 的报告可复现。
- 格式、Clippy 和全量测试通过。

## S1. 策略 DSL、校验器和本地模板

工作量：4–6 天。  
依赖：S0。  
目标：让策略成为安全、可保存、可回测的领域对象。

任务：

- 创建 `domain/strategy`。
- 定义 `StrategySpec`、`Expression`、`IndicatorRef`、`ExitRule` 和 `PositionRule`。
- 完成 JSON 序列化、反序列化和 schema version。
- 编写结构校验、参数范围校验、复杂度限制、退出条件校验和 warm-up 计算。
- 实现规范化序列化和 SHA-256 策略哈希。
- 编译成确定性的 `CompiledStrategy`。
- 首批本地模板：
  - MA 趋势回踩。
  - RSI 超卖恢复。
  - N 日高点突破。
  - BOLL 均值回归。
  - 放量趋势确认。
- 将原有三个 `BacktestRule` 适配到新策略定义，避免同时维护两套逻辑。

验收：

- 非法 JSON、未知指标、未来 lag、超限周期和无退出策略被拒绝。
- 相同语义的规范化策略得到相同哈希。
- 五个本地模板在合成数据和固定 fixture 上产生预期信号。
- `domain/strategy` 不依赖 GPUI、HTTP 和文件系统。

## S2. SQLite 数据集与实验持久化

工作量：5–8 天。  
依赖：S0；可与 S1 后半段并行，但合并需保持独立 PR。  
目标：把临时可见 K 线升级为可冻结、可复现的本地数据集。

推荐技术：`rusqlite` + bundled SQLite，启用 WAL；引入前检查跨平台构建和许可证。

建议表：

- `schema_migrations`
- `instruments`
- `daily_bars`
- `dataset_manifests`
- `dataset_members`
- `strategies`
- `experiments`
- `experiment_candidates`
- `backtest_runs`
- `backtest_trades`
- `daily_equity`
- `paper_signals`

任务：

- 定义 `DatasetRepository` 和 `ExperimentRepository` trait。
- 实现 SQLite migration、事务、备份和恢复路径。
- 从现有 KlineProvider 批量抓取并增量更新日 K。
- 校验日期有序、OHLC 合法、重复记录和异常价格。
- 冻结股票池成员和 K 线内容，生成 DatasetManifest。
- 支持离线重新打开历史实验。
- 数据库不得保存 AI API Key；继续使用现有系统凭据库。

验收：

- 重复抓取不会重复插入日 K。
- 数据改变会产生新 DatasetId，不会覆盖旧实验依赖的数据。
- 中断写入不会产生半完成实验。
- 数据库迁移具有升级和失败回滚测试。
- 现有 JSON 配置、组合和日记不强制迁入数据库。

## S3. 多标的组合回测引擎

工作量：5–8 天。  
依赖：S1、S2。  
目标：支持多个策略在冻结股票池上的组合级批量回测。

任务：

- 实现交易日历对齐和多标的逐日事件循环。
- 信号在收盘计算，订单在下一有效交易日执行。
- 实现现金、仓位、最大持仓数、整数手、费用和滑点。
- 支持固定持有、表达式退出、止损、止盈和最长持有。
- 明确同日多信号的排序规则；首版使用稳定、可复现的排序，不使用随机选择。
- 支持取消令牌、进度快照、单标的失败隔离和结果缓存。
- 保存订单拒绝和无法成交原因。
- 生成逐日组合权益和逐笔交易。

指标：

- 总收益、年化收益和年化波动。
- 同期基准和超额收益。
- 最大回撤、回撤持续时间。
- Sharpe、Sortino、Calmar。
- 胜率、平均盈利、平均亏损、盈亏比和 Profit Factor。
- 交易数、持仓天数、市场暴露、换手率。
- 毛收益、总成本和成本占毛收益比例。
- 按年份、标的和市场状态拆分。

验收：

- 50–100 只股票、5 个策略可以完成批量回测。
- 同一输入的订单顺序和结果确定一致。
- 任务可取消，取消后实验状态正确且可重新运行。
- 单个标的数据异常不会造成整个进程崩溃。
- 报告可以下钻到逐日权益和逐笔交易。

## S4. AI 结构化策略生成

工作量：4–6 天。  
依赖：S1；推荐在 S3 稳定后接入。  
目标：让 AI 提出多个可解释、可校验的策略假设。

任务：

- 从 `src/data/ai.rs` 抽取通用 `LlmClient` trait 和 HTTP/CLI 实现。
- 保持现有 AI 点评行为与配置兼容。
- 定义 `StrategyGenerator` 输入和 `StrategyBatchDraft` 输出。
- 提示中提供完整 JSON Schema、白名单指标和参数范围。
- 默认生成 3–5 个策略，最大不超过 8 个。
- 要求策略逻辑多样化，避免只改变一个周期参数。
- 对返回文本进行大小限制、JSON 提取、反序列化和本地校验。
- 校验失败最多请求 AI 修复一次；仍失败则保留错误并回退本地模板。
- 保存模型名、传输方式、提示版本、原始响应摘要和校验结果。
- 不把 API Key、完整本地路径和无关用户数据写入实验。

AI 输入可以包含：

- 用户研究目标，如趋势、反转、低回撤或低换手。
- 市场、周期、股票池元数据和风险限制。
- 允许的指标、操作符和成本假设。
- 训练数据的高层描述。

AI 输入不得包含：

- 封存测试集的策略结果。
- 为迎合某个测试区间而提供的未来信息。
- 真实持仓账户秘密或 API Key。

验收：

- AI 返回的自然语言和代码块不会被执行。
- 未通过本地校验的策略无法进入回测队列。
- 重复策略通过规范化哈希去重。
- AI 不可用时本地模板仍可完成完整实验。

## S5. 样本外、稳健性和晋级规则

工作量：5–8 天。  
依赖：S3、S4。  
目标：控制多策略生成带来的选择偏差和过拟合。

数据划分：

- 训练集：允许构造策略和调整参数。
- 验证集：用于选择候选和检查参数稳定性。
- 封存测试集：最终只运行一次；查看结果后该策略视为已消费测试集。
- 滚动样本外：多个按时间前进的训练/验证窗口。

任务：

- 实现固定时间切分和 walk-forward 配置。
- 实现牛市、熊市、震荡和高波动状态分组；状态定义必须只使用当时可见数据。
- 实现成本和滑点 2 倍压力测试。
- 实现参数邻域稳定性测试。
- 统计单一标的、行业、年份和窗口的收益集中度。
- 记录本次实验尝试的全部策略和参数数量。
- 优先使用按时间或标的分块 bootstrap，输出不确定性区间。
- 将晋级判定写成纯领域函数和可版本化配置。

建议默认晋级门槛：

- 交易数不少于 50。
- 覆盖标的不少于 20 只。
- 至少 3 个滚动样本外窗口。
- 扣除成本后样本外超额收益为正。
- 成本和滑点翻倍后不出现整体失效。
- 最大回撤不超过用户设置的风险预算。
- 单一股票或单一年份贡献不超过总净收益的 30%。
- 相邻合理参数结果没有断崖式恶化。
- 不能仅因胜率高而晋级。

门槛是研究默认值，不是投资建议；必须通过版本化配置保存。

证据等级：

```text
无证据
→ 样本不足
→ 样本内探索
→ 样本外观察
→ 多阶段稳定
```

产品结论：

```text
淘汰 | 继续研究 | 模拟盘候选
```

验收：

- AI 无法修改晋级结论。
- 任一硬性门槛失败都有机器可读原因和用户可读解释。
- 测试集被查看后，实验记录 `test_consumed_at`。
- 修改参数后必须产生新策略版本，不能覆盖原测试结果。

## S6. 策略实验室 UI

工作量：4–6 天。  
依赖：S3、S4、S5。  
目标：在 GPUI 中形成完整、可下钻的实验工作流。

建议页面：

1. 实验配置：目标、股票池、时间区间、风险、策略数量。
2. 策略草案：显示假设、规则、校验结果和来源。
3. 运行进度：总体进度、当前策略、取消和失败信息。
4. 排行榜：确定性排名、证据等级和晋级结论。
5. 证据报告：资金曲线、回撤、年度、市场状态和交易明细。
6. 模拟候选：保存策略版本并进入每日观察。

每张策略卡必须展示：

- 策略假设和规范化规则。
- 生成来源：本地模板或 AI 模型。
- 数据集、基准、成本、成交和策略版本。
- 样本内、验证、测试和滚动窗口结果。
- 最大回撤、交易数和成本敏感度。
- 淘汰或晋级的明确原因。
- AI 解释，并标注“AI 生成，不参与确定性评级”。

状态放入 `features/strategy_lab/state.rs`，不得把实验列表、进度、报告和输入控件全部加入 `AppState`。

验收：

- 用户可从排行榜下钻到逐笔交易。
- 取消任务后界面状态与数据库状态一致。
- 关闭并重启应用后可以恢复已完成实验。
- AI 解释缺失或失败不影响本地报告。
- 小窗口下核心操作仍可访问，并增加布局测试。

## S7. 模拟盘与发布验收

工作量：3–5 天。  
依赖：S6。  
目标：用新数据验证策略行为，而不是只依赖历史回测。

任务：

- 每日对保存的模拟候选运行信号。
- 记录理论入场、理论退出、无法成交和错过原因。
- 信号和模拟交易幂等，重复运行不会重复创建。
- 比较模拟结果与回测中的交易频率、滑点、持有期和风险。
- 支持导出策略、报告和模拟记录。
- 完成数据库恢复、跨平台构建和性能测试。

进入进一步研究的最低观察条件：

- 连续运行 4–8 周，或产生至少 20 个新信号。
- 无数据穿越、重复信号和状态错乱。
- 实际模拟行为与策略定义一致。
- 实际模拟滑点没有明显超过压力测试假设。

即使满足以上条件，也只能表示“值得继续研究”，不能保证未来盈利。

## 7. 排名与总结规则

排行榜使用“硬门槛 + 多目标展示”，不建议把所有指标压成一个神秘总分。

先执行硬门槛：

- 数据完整性。
- 最低交易数和覆盖标的数。
- 成本后收益。
- 最大回撤预算。
- 样本外和压力测试。
- 集中度和参数稳定性。

通过硬门槛后，再按用户目标排序：

- 低回撤目标：优先 Calmar、回撤持续时间和压力测试稳定性。
- 趋势目标：优先样本外超额、Profit Factor 和市场状态覆盖。
- 低换手目标：优先成本后超额、换手率和持有期稳定性。

AI 总结输入只包含已计算好的报告，不让模型重新计算数值。总结必须：

- 说明策略假设。
- 比较候选之间的主要差异。
- 指出样本外、回撤、成本和集中度风险。
- 引用本地报告数值，不编造数据。
- 使用“研究候选”措辞，不使用保证盈利或强制买卖措辞。

## 8. 测试与质量门禁

### 8.1 单元测试

- 策略 JSON、schema version 和规范化哈希。
- 所有表达式操作符和指标 warm-up。
- 未来数据不可见。
- 订单生成、费用、整数手和现金约束。
- 止损、止盈、最长持有和条件退出。
- 逐日权益、基准、回撤和风险指标。
- 晋级门槛和证据等级。

### 8.2 属性与变形测试

- 改变未来数据不改变过去信号。
- 增加成本不能提高净收益。
- 删除一笔盈利交易不能提高总净利润。
- 相同输入多次运行结果一致。
- 打乱数据库读取顺序不改变确定性订单顺序。
- 取消任务不会留下 Completed 状态。

### 8.3 集成测试

- 从 StrategySpec 到回测报告的完整 fixture。
- 多标的交易日历和停牌 fixture。
- SQLite migration、回滚和离线恢复。
- AI 无效 JSON、超限结构、重复策略和修复失败。
- UI 创建实验、取消、恢复和下钻。

### 8.4 性能基线

记录固定硬件和 release 构建下：

- 100 只股票 × 5 个策略 × 1000 根日 K 的运行时间。
- 峰值内存。
- 数据库体积。
- UI 首次打开实验和切换报告耗时。

首版目标以不阻塞 UI、可取消、峰值内存可控为主，不提前做复杂并行优化。

### 8.5 每个 PR 的必要检查

```bash
rtk cargo fmt --all -- --check
rtk cargo clippy --all-targets -- -D warnings
rtk cargo test --all-targets
```

涉及数据库、打包或 feature 时还需：

```bash
rtk cargo check --all-targets --no-default-features
```

联网数据源测试继续保持显式 ignored，不得让普通 CI 依赖公网稳定性。

## 11. 风险登记

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 免费行情接口不稳定 | 数据缺失、实验失败 | 本地缓存、数据校验、不可变数据集、失败重试 |
| 仅有当前股票池 | 幸存者偏差 | 报告强制提示；以后接入历史成分股和退市数据 |
| 前复权历史被修订 | 旧结果不可复现 | 冻结 Candle 内容并使用内容哈希 |
| AI 生成大量相似策略 | 多重筛选过拟合 | 候选上限、规范化去重、记录尝试次数、封存测试 |
| AI 输出不合法 | 无法运行或安全风险 | 白名单 DSL、本地校验、复杂度限制、只修复一次 |
| 回测性能影响 UI | 卡顿或内存增长 | 后台任务、进度快照、取消、基准测试、结果缓存 |
| SQLite 跨平台打包 | CI 或安装包失败 | 独立 PR 验证四平台，优先 bundled SQLite |
| 新状态继续堆入 AppState | 架构回退 | 使用独立 feature state/controller，代码评审门禁 |
| 用户误解为投资建议 | 产品与合规风险 | 研究措辞、来源和限制提示、不接真实交易 |

## 12. 总体验收清单

- [ ] AI 一次可生成 3–5 个不同策略。
- [ ] 所有策略通过白名单 DSL 表达，不执行任意代码。
- [ ] 策略、数据集、成本和报告均有稳定版本。
- [ ] 相同输入结果可复现。
- [ ] 修改未来数据不影响历史信号。
- [ ] 多标的回测使用逐日资金和真实现金约束。
- [ ] 报告包含基准、成本、样本量、回撤和不确定性。
- [ ] 样本外和压力测试失败的策略不会晋级。
- [ ] AI 不接触封存测试结果后重新修改同一策略。
- [ ] AI 不能改变本地排名和证据等级。
- [ ] 实验可以取消、恢复、导出和离线查看。
- [ ] 模拟信号幂等，不连接真实券商。
- [ ] 新功能没有继续膨胀 legacy AppState。
- [ ] 全量格式、Clippy、测试和跨平台检查通过。
